# Deploying WordRush to Render

The whole stack is described in [`render.yaml`](../render.yaml), a Render Blueprint:

| Resource | Render type | What it does |
|---|---|---|
| `wordrush` | Web service (Docker, `backend/Dockerfile`) | Spring Boot API + WebSockets, and serves the built React app. One public URL for everything. |
| `wordrush-db` | Render Postgres | Accounts and (later) game history. Flyway creates the tables on startup. |
| `wordrush-kv` | Render Key Value (Redis-compatible) | Live rooms, rounds, scores and timers. |

Everything is on the free plan in one region (Oregon). The database and Key Value accept connections only from your Render services.

## 1. Push the repo to GitHub

Create an empty repository on GitHub (private is fine; don't add a README or .gitignore), then from the project folder:

```bash
git remote add origin https://github.com/<you>/wordrush.git
git push -u origin main
```

## 2. Create the Blueprint on Render

1. Sign in at https://dashboard.render.com (signing in with GitHub is easiest).
2. Click **New > Blueprint**.
3. Connect your GitHub account if asked, then click **Connect** next to the `wordrush` repo.
4. Give the Blueprint a name (e.g. `wordrush`) and keep the branch as `main`. Leave the Blueprint path as `render.yaml`.
5. Review the list. It should show three new resources: `wordrush`, `wordrush-db`, `wordrush-kv`. Click **Deploy Blueprint**.

You don't need to type any secrets: `JWT_SECRET` is generated by Render, and the database and Key Value connection details are wired in by the Blueprint.

## 3. Watch the first deploy

- Postgres and Key Value are ready within a minute or two.
- The web service builds the Docker image (frontend, then backend). **The first build takes about 5–10 minutes.** Open the `wordrush` service and watch its **Logs**.
- It's live when the log shows `Started WordRushApplication` and the service turns green. Render only switches traffic over once `/actuator/health/readiness` returns UP (database and Key Value both reachable).

Your URL is shown at the top of the service page, usually `https://wordrush.onrender.com` (Render adds a suffix if that name is taken).

## 4. Play with friends

Open the URL, pick a nickname, start a room, and send friends the invite link from the lobby. It works on phones too.

## Updating

Every push to `main` redeploys automatically. Changes to `render.yaml` are applied by the Blueprint too.

## Things to know about the free plan

Check Render's pricing page for the current limits; these are the ones that matter here:

- **Cold starts.** A free web service sleeps after about 15 minutes without traffic. The next visitor waits while it wakes and the JVM starts (often 30–60 seconds). Open the site a minute before a game night. A paid instance never sleeps.
- **Free Postgres expires** a while after creation (30 days at the time of writing) unless you upgrade it. Live games don't depend on it beyond sign-in, but accounts are stored there.
- **Free Key Value has no persistence.** If it restarts, rooms in progress are lost. Players just create a new room.
- **512 MB of memory.** The image is tuned for it (`JAVA_TOOL_OPTIONS` in the Blueprint).

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Build fails in the frontend stage | Run `cd frontend && npm ci && npm run build` locally; fix any TypeScript errors. |
| Deploy fails health checks | Logs will show the cause. `APPLICATION FAILED TO START` with `JWT_SECRET` means the env var is missing: check the service's **Environment** tab. Connection errors mean Postgres or Key Value isn't ready yet; redeploy once they're green. |
| Page loads but stays on "Reconnecting…" | The WebSocket was refused. The app allows its own Render URL automatically (`RENDER_EXTERNAL_URL`). If you add a custom domain, set `ALLOWED_ORIGINS=https://your.domain` on the service. |
| Everything is slow to start | Cold start on the free plan (see above). |

## Run the production image locally

The same image runs locally with Docker Compose, which is a good check before pushing:

```bash
docker compose -f infra/docker-compose.yml --profile app up --build
# then open http://localhost:8080
```
